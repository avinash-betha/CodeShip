# Known boundaries and remaining hardening

This is a functional, integrated beta. It is not a verified implementation of every possible enterprise visual-editor capability.

1. **Responsive intent:** analysis uses seven actual rendered widths. Recommendations are based on measured constraints at those samples, not an exact binary search for every failure boundary. It can miss problems between samples, late-loading remote content, intentional clipping, absolute-positioned overlap, and complex writing modes. Low-confidence overlap suggestions need an explicit alternative choice. Re-analyze after applying changes. Automated layout repair does not infer arbitrary design intent.
2. **Reusable instances:** saved blocks create editable snapshots with stable definition references. Editing a definition does not propagate changes or merge overrides into previous instances. Exported pages preserve their expanded visuals; reusable source files are available for application developers to compose further.
3. **HTML fidelity:** the builder supports semantic/custom HTML and common forms/tables/media, but its nesting checks are guidance for common content models, not the full HTML specification. Mixed inline text imports into editable spans. Imported scripts, executable attributes, embedded browsing contexts, CSS imports, and unsafe URLs are explicitly rejected or removed with a report. SVG with uncommon case-sensitive tags/attributes may need additional exporter adapters. Relative third-party assets need a valid URL or uploading to Assets.
4. **CSS:** safe modern/unknown CSS is preserved with PostCSS. Structured controls address common properties; advanced CSS is authored in Monaco. Properties using semicolons inside a value should be edited in source. The visual controls currently display explicit declarations for their scoped selector, while inherited values remain identified as inherited. Export-specific scoping and global cascade behavior warrant review for complex multi-page imports.
5. **Application behavior:** the fixed local runtime supports class/text/navigation, filters, sorting, pagination, panels, dialogs, tags, chat messages, range output and kanban pointer/drag reordering. Arbitrary JavaScript, backend logic, authentication, CRUD services, framework data-binding authoring, React state machines, and user-defined event code are outside the implemented interaction model. Screen templates provide editable real interfaces, not fabricated working backends.
6. **Canvas:** eight handles, aspect/size constraints, freeform/flex/grid/flow, nudging, alignment, spacing drags and snapping are implemented. There is no full constraint solver, rotation tool, proportional multi-selection scale tool or cross-page clipboard. Large changes redraw the iframe; selected elements are revealed, but every scroll/focus position is not preserved through all structural edits.
7. **Storage:** the desktop app stores permanent native files, immutable asset versions and retained backups using serial atomic writes. It does not implement cross-process conflict merging or network-drive locking. Browser development retains IndexedDB and its browser eviction/quota limits. Save errors are surfaced; neither local atomic writes nor retained backups replace independent backups.
8. **Export coverage:** representative independent project and reusable-component builds are automated. Selected CSS extraction retains uncertain ancestor selectors with warnings; complex selectors and animation shorthands can require destination review. Arbitrary imported attributes, uncommon SVG, external fonts/media, duplicate page paths, nested relative navigation, and application-specific deployment bases still require review. Framework versions are pinned to compatible supported major lines. A custom-element tag and its markup are exported; its external implementation must be supplied by the application developer.
9. **Hardening:** no independent penetration test, exhaustive assistive-technology review, production telemetry, schema-migration archive of real legacy projects, or sustained very-large-project benchmark has been performed. The editor works without paid services and is runnable; calling it fully production-ready would exceed the available evidence.

Continuation priority: add comprehensive target-adapter fixtures for form/SVG/custom attributes; implement linked component definitions with override-aware propagation; refine measured breakpoints adaptively; preserve iframe view state through edits; expand keyboard/assistive-technology and large-project tests.

Dependency-audit scope: the production dependency graph passes with Monaco 0.57 and a DOMPurify 3.4.17 override. Monaco's distributed editor bundle also contains an upstream vendored DOMPurify 3.4.15 copy; a package-manager audit does not inspect that bundled copy. CodeShip's import/preview trust boundary uses its own validation, escaping, sandbox and CSP rather than Monaco's sanitizer. Continue tracking upstream bundle updates; the dependency result is not an independent security audit.
